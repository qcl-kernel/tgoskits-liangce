## 已发现的第一个真实兼容缺口（已解决，2026-08-18）

官方 `os/axvisor/src/virtio_net.rs` 曾固定请求 Guest MMIO `0x0a000000` 和 INTID 48；
竞赛 Linux 的 passthrough root block 也占用 Guest `0x0a000000`。因此官方双 ArceOS demo
不能直接替代 Linux+Zephyr 配置。

确定并已落地方案（本地提交 `7296381cc`）：

1. 保持 `model="virtio-net"` 和同一官方 backend，不注册第二套网络设备模型；
2. 普通 VirtIO-net MMIO 与 wired IRQ 已改为 resolved graph 的 `ResourceRequest::Auto`，
   让 AArch64 资源池避开 passthrough/Guest RAM/保留区；
3. 不再把 `0x0a000200/49`、`0x0a000400/50` 作为手写配置输入；实际值由 resolved graph
   唯一决定，并由 final DTB、runtime resource report 和 capture 三方绑定（待 P4 runtime）；
4. 已先加 axdevice 宿主回归 `fixed_linux_root_block_and_auto_virtio_net_coexist`（Fixed
   0x0a000000/48 必冲突、Auto 解析到 root 之外），再改 production requirements；
5. 门禁全绿：fmt、axdevice 47、axvirtio-common 39、axvirtio-net 18、xtask clippy 4/4、
   正式 AArch64 AxBuild（官方双 ArceOS demo guest 镜像已按官方 run.sh 构建）。
   另新增 Python 源码合同 `check_axvisor_virtio_net_auto_resources.py` 并接入 CI。

该修改只解决资源规划冲突，不证明 Guest 已枚举 NIC，更不证明 Guest IP。官方结构不存在
宿主 `cargo test -p axvisor` 路径，原补丁内两项 unit test 已等价迁移（见提交说明）。
