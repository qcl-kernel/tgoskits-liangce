## 2026-08-19 快照：L7 里程碑——双 Guest vnet0 100/100 ICMP 零丢包

在 P4-NET-D/E 落地（`60f98f2d1`/`d660e49d4`）基础上，经 `59818a24e`（level IRQ）与
`5610ce224`（ICMP checksum 字节序修复）取得**首个真实双 Guest mediated-vnet0 成功**：

- **`TGOS_LINUX_L3_SMOKE sent=100 received=100 loss=0`**：Linux 10.77.0.1 → Zephyr
  10.77.0.2 经 vnet0（0x0b000000/INTID 32）双向 102/102 帧投递，Linux 100/100 ICMP 零丢包；
  runner `success=true / guest_network_completed`，双 READY oracle 命中。
- **根因**：Linux 把大端 ICMP checksum 以主机字节序存入（little-endian 下线上字节反转
  0xadbe→0xbead），Zephyr `net_calc_chksum_icmpv4` 校验失败丢弃全部 echo；修复为
  `htons()` 后全通（Zephyr echo handler 处理 101 次含 probe）。
- 分支 ahead 11（新增 `5610ce224`），仅本地未 push。
- **仍未完成**：Zephyr→Linux 反向主动 ICMP、UDP/TCP/ICPC（TEST-012..015）、P5/P3；
  Zephyr 侧 eth_virtio_net/icmpv4/ipv4 诊断 printk 保留在锁定 Zephyr 缓存，正式 evidence
  run 前需清理与重新完整构建；Linux 启动偶发卡顿仍存在但未影响本成功 run。
- **Zephyr 板级适配记录**：`boards/qemu/cortex_a53/Kconfig` 禁用 PCIe/e1000 select（备份
  `.contest-bak`）、入口 0x4000117c、overlay 对齐 resolved 值、prj.conf 网络配置——均在
  锁定 Zephyr 缓存，fresh 环境需重放（见交接）。
