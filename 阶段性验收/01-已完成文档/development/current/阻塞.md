## 四、阶段性技术风险

### R-001：WSL2 与容器内的 CPU 亲和性测量

- 影响：宿主 Windows 调度会引入额外噪声，不能把 WSL/QEMU 数据直接等同于裸机硬实时结果。
- 应对：固定测试环境和负载，重复多轮，报告最大值和高分位数，并明确 WSL2 误差来源。
- 后续选择：主线先完成 QEMU 可复现数据；有开发板后补充原生或板卡结果。

### R-002：VirtIO-net 外层拓扑已验证，Guest 侧 DMA/IP 尚未闭环

- 影响：阶段 4 的 Linux/Zephyr IP 链路可能需要补充 AxVisor 虚拟设备或 QEMU 后端配置。
- 当前事实：2026-07-26 live probe 已验证外层 QEMU 三槽位：block/net/net 分别为 bus 0/1/2、MMIO `0x0a000000/200/400`、INTID 48/49/50；两网卡接同一内部 hub 0，11 项证据哈希全部通过。
- 已解决：SPI 现按实际 pinned pCPU/MPIDR 路由，Linux SMP2 与 Zephyr 单 Guest 都启用了 GPPT GIC，并在最新上游 QEMU 回归通过。
- 仍阻塞：显式白名单、Zephyr polling 镜像和单 Guest PL011 drain/demux 已有实机证据，single-Guest 最终 Guest DTB、`MapAlloc` 查询，以及 r21 Linux `MapReserved`/Host carveout/shell 均已完成；但 Zephyr DMA 隔离、Linux synthetic PL011 完整 console、双 Guest 与 IP 尚未解决。外层槽位、Linux r21 passthrough console 和单 Guest PL011 通过都不等于双 Guest/IP 通过。
- 应对：新配置使用 VM1 pCPU0/1、VM2 pCPU2，pCPU3 留宿主；网络不复用 outer slot1/2，两个 Guest-FDT 节点由 AxVisor 分别合成并绑定独立 mediated frontend。
- 实现边界：当前代码没有可直接使用的 AxVisor VirtIO-net factory。唯一 v1 路线是补 `VirtioNetFactory`、受控 Guest-memory copy capability、独立 queue/IRQ/generation、bounded 二端口 `vnet0` 和内部 capture；固定 identity RAM 与 outer slot passthrough 均已否决。
- 禁止替代：主数据链路不得改用 HyperCall、共享内存、裸 MMIO 或 vsock。

### R-003：实时化改动范围过大

- 影响：容易在两个月内陷入调度器重写，无法形成可复现闭环。
- 应对：只选 1 至 2 个有基线数据支撑的关键路径，要求能开关、能对照、能解释。

### R-004：AI 任务喧宾夺主

- 影响：YOLO、Qwen 或复杂训练会消耗大量时间，却不能替代实时化和网络评分项。
- 应对：坚持小型 MLP 和简单控制对象，以端到端闭环与量化效果为目标。

### R-005：GIC 路由回滚不等于完整 SPI 状态恢复

- 当前事实：已实现并测试 `GICD_IROUTER` 首次快照与 reset/destroy/Drop 幂等恢复。
- 剩余风险：enable、pending、active、group/group modifier、priority 和 trigger config 尚未快照/恢复。
- 应对：在实机 passthrough 和 VM 重启/销毁压力测试前，另立 IRQ quiesce + 完整状态事务设计；文档和演示只表述为“路由回滚已完成”。

### R-006：固定 HPA 已与宿主 allocator 闭环，passthrough DMA 仍未闭环

- 当前事实：高风险设计与 `MapReserved` Phase A/B 已完成；someboot 专用 carveout 在初始化内存描述符时进入 Reserved，独立 manifest 经 axplat/axhal 暴露，AxVM 按 VM ID/HPA/size 精确授权并在任何映射副作用前拒绝。r20/r21 已关闭 Linux `MapReserved` 单 Guest shell/host-carveout 低层链。r22 静态准备了独立 `0x180000000..0x180200000` DMA guard；2026-08-10 的 Rust 单测/Clippy/rustfmt 与两次正式 AArch64 AxBuild 均通过，30/30 Python 合同通过。r23 在同一 identity-bound QEMU 链中记录 guard `RESERVED` line 118 和 `ALLOCATOR_EXCLUDED` line 195，`reserved_cover=1`、`free_overlap=0`，并与 Host DTB、capture-chain、Guest-DTB、stage-2 和 Linux shell 聚合绑定。
- 影响：若把 `MapReserved`/固定 identity RAM 用作 Zephyr VirtIO DMA，而宿主仍可分配同一页，会破坏宿主或其他 VM 内存。
- 未解除边界与应对：r23 证明 guard 被 host allocator 排除，但没有发出或观测真实 DMA 请求，不能证明 DMA isolation。下一步使用已接入 CI 的 controlled VirtIO DMA-effect 合同，以一次 nonce/hash 绑定具体设备请求、payload 前后与 guard 前后四份只读 host-physical capture。即使单次探针通过也不是通用隔离；P4 已另行固定为软件拷贝 mediated frontend + bounded `vnet0`，禁止把固定 RAM 描述为 DMA-safe，也永久禁止把 Zephyr 网络改回 outer slot2 passthrough。

### R-007：single-Guest FDT 动态证据已完成，双 Guest 仍待验证

- 当前事实：r13 已在同一 QMP 会话完成 identity-bound single-Guest capture（PID/start-time/boot ID/UID/exe/cmdline/socket inode/`SO_PEERCRED`/QEMU name/nonce，`stop/pmemsave/cont`），并对 DTB 完成 `dtc` 静态语义审计。r16 在同级 single-Guest QMP run 中再次完成 DTB 审计并发布 stage-2 report；r21 的 7,540-byte Guest DTB 两次 `dtc` DTS hash 均为 `399e9c...`，semantic validator 通过、root `/reserved-memory=0`，且绑定 Host DTB/VM config/raw log/status 哈希 chain。
- 未完成边界：上述仍仅覆盖 single Guest；r21 证明 Linux `MapReserved` shell 与 host-carveout marker，不证明 DMA、双 Guest FDT/启动、30 分钟稳定性或 IP。
- 应对：先完成 DMA nonce/hash，再为双 Guest 独立采集 marker、identity、plan、execution、segments、DTB/DTS、chain 与 SHA-256，随后完成 short smoke/30 分钟；不得复用 single-Guest 结果。

### R-008：Zephyr 独立 console 已有实机输出，完整动态 gate 未完成

- 当前事实：r7/r8 分别保留 ANSI 前缀与 CRLF 归一化失败审计；r9 已证明 strict demux、222 连续帧、718 bytes、无 drop/DMA、10 样本/PASS、unsafe=0，整包 `passed` 且 521 项 checksum 全通过。
- 影响：Zephyr 单 Guest输出链已经闭环，但 Linux console、双 Guest同时可归属输出仍未完成；仍不能用宿主物理 PL011 共享替代。
- 已知边界：drain 当前只覆盖默认 VM 生命周期；没有 sink 两阶段确认/失败重试；设备销毁重建后 generation 连续性尚未建立。
- 应对：下一步完成 Linux 单 Guest、双 Guest drain/demux 与故障注入；全部动态 gate 通过前不得解除 `blocked_dma_console`。

### R-009：Rust 动态验证按源码快照分级

- 当前事实：r21 后快照的历史结论保留；2026-08-10 已对新增 DMA guard delta 单独完成 `someboot`/`axplat-dyn`/`ax-hal`/`ax-runtime` 测试、生产代码严格 Clippy、最终 rustfmt，以及带 r23 VM config 的正式 AArch64 AxBuild。r23 随后通过真实 QEMU 验证。
- 影响：DMA guard delta 可以升级为“Rust 门禁 + Host allocator/runtime observation 已完成”，但仍不能升级成 passthrough DMA effect 或 DMA isolation。
- 当前状态：本项针对 DMA guard delta 的快照分级缺口已解决；实际 DMA effect 继续由 R-006 跟踪。

### R-010：Linux synthetic PL011 只具备 earlycon 静态合同

- 当前事实：最终节点故意不含物理 IRQ/DMA/HPA，且当前也不提供 clock；bootargs 增加 `earlycon=pl011,mmio32`。标准 Linux `amba-pl011` 完整 probe/startup 通常仍依赖 clock 与 IRQ，静态 FDT 合同不能证明常规 tty、boot-console 交接或 `/dev/console` 可用。
- 影响：可能只能看到早期内核输出，无法复用历史 shell marker；若误判为完整 console，会让双 Guest runner 在没有有效 Guest 进度证据时假成功或超时。
- 应对：在锁定 kernel 上先做单 Guest red-first 测试，保存最终 bootargs/DTB/DTS 与完整 frame；明确验证 earlycon 持续范围、唯一 marker 和 `/dev/console`。若交接失败，选择显式保留 boot console、实现真正的 VM-local IRQ/clock 支持，或回退 Phase 0；禁止恢复物理 INTID 33。
- 当前状态：未解决，属于 console 动态 gate。
