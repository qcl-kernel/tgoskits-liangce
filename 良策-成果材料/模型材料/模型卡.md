# 轻量神经网络控制器模型卡

## 1. 用途

本模型用于 Linux Guest 中的一阶温度对象控制。Linux 接收 Zephyr Guest 发布的状态，执行推理并通过 ICPC CONTROL 消息下发加热占空比；Zephyr 负责最终动作应用、对象更新和 500 ms 失联安全保护。

模型仅服务于固定实验对象和已登记的输入范围，不用于安全认证，也不取代 Zephyr 侧的独立安全边界。

## 2. 结构与输入输出

| 项目 | 规格 |
|---|---|
| 网络结构 | `3→8→1` 多层感知机 |
| 隐藏层 | 8 个单元，ReLU |
| 输出层 | 1 个单元，sigmoid |
| 输入 1 | 测量温度 `measured_mC` |
| 输入 2 | 目标温度 `target_mC` |
| 输入 3 | 上一周期占空比 `previous_duty_q16_16` |
| 输出 | `[0,1]` 范围的加热占空比，量化为 Q16.16 |
| 推理位置 | Linux Guest |
| 控制周期 | 100 ms |

## 3. 对照与评估场景

固定 PI 控制器与模型使用相同网络、协议、对象和采样窗口。固定场景为 180 s，初始与环境温度 25,000 mC，目标温度 55,000 mC，60 至 90 s 每周期注入 -150 mC 扰动。三个固定 seed 使用相同故障清单，保证两种控制器可配对比较。

主要评估指标为 RMSE、IAE、稳定时间、超调量和 Linux 同钟闭环时间。只有当前候选版本的 Guest 运行数据满足测试判据后，才报告模型相对对照的量化效果。

## 4. 可复现工件

当前候选的模型、元数据、数据清单、黄金向量及生成/验证工具位于 `源码/tgoskits/apps/contest/linux-ai-controller/model/` 及相邻源码目录。最终审核应确认以下工件完整且与候选提交一致：

- 模型权重与格式版本；
- 输入归一化和输出量化参数；
- 训练或确定性生成配置、随机种子和依赖版本；
- 数据 schema、数据生成说明和数据清单；
- 黄金输入输出向量；
- 参考实现与 Guest 部署实现的一致性检查；
- 每个工件的大小和 SHA-256。

最终复核应能够重建相同模型字节，并验证部署输出与参考输出位于规定量化误差范围内。

## 5. 安全边界与限制

- 非有限输出、模型版本不匹配或推理失败时，不得下发有效控制动作；
- 输出在进入协议前必须检查范围并量化，Zephyr 再次验证请求身份、目标和动作范围；
- 模型或 Linux 进程异常不能关闭 Zephyr 的 500 ms 看门狗；
- 本模型只针对规定的一阶温度对象与输入范围，不宣称适用于真实工业设备、未测试对象或其他硬件平台；
- 主机黄金向量通过不等于 Guest 端推理和端到端闭环已通过。
