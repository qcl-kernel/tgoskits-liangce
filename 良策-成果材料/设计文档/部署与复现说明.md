6. 生成测试报告、统计结果、证据索引和校验和。

## 2. 目标环境

| 类别 | 要求 |
|---|---|
| 主机 | 支持 QEMU AArch64 的 Linux 环境；CPU、内存和磁盘满足双 Guest 构建与运行 |
| 虚拟机模型 | QEMU `virt`、Cortex-A72、GICv3、4 vCPU、8 GiB |
| Hypervisor | 成果源码锁定的 AxVisor 版本 |
| Guest | Linux，至少 2 vCPU；Zephyr，1 vCPU |
| 网络 | AxVisor 内部 `vnet0`，不依赖宿主 TAP、bridge、NAT 或外部 NIC |
| 工具链 | Rust、AArch64 交叉工具链、Python、C/CMake、QEMU；最终清单登记精确版本 |
| 输入工件 | Guest 镜像、配置、模型、依赖；每项必须登记来源、大小和 SHA-256 |

## 4. 复现顺序

### 4.1 完整性检查

- 校验 `SHA256SUMS.txt`；
- 检查所有外部依赖下载地址可访问且哈希一致；
- 记录源码基线、候选提交号和工作树状态；
- 确认没有使用开发机缓存或未登记文件补齐构建。

### 4.2 静态与主机合同

- 检查格式、许可证、链接、配置 schema 和禁止项；
- 运行协议黄金向量、模型黄金向量、网络边界、故障状态机和证据 validator；
- 每条命令记录标准输出、标准错误和退出码。

### 4.3 目标构建

- 完成适用的 Rust 严格检查和 AArch64 目标构建；
- 构建 Linux 智能控制程序和 Zephyr 控制程序；
- 登记最终二进制、Guest 镜像、模型和配置哈希。

### 4.4 双 Guest 启动

- 启动 QEMU 与 AxVisor；
- 验证 Linux 使用 2 vCPU、Zephyr 使用 1 vCPU，CPU 归属无重叠；
- 保存最终 FDT、设备资源、中断、启动参数、镜像身份和双端控制台；
- 确认每个 Guest 仅枚举自己的 VirtIO-net 节点。

### 4.5 网络与协议

- 验证固定 MAC、IPv4 和仅直连路由；
- 双方向分别执行 100 个 ICMP echo，检查丢包与地址偏差；
- 验证 UDP 46000 主链路、CONTROL 确认与有限重试；
- 注入 ACK 丢失和会话切换，验证 500 ms 过期、TCP 46001 回退和旧会话失效；
- 保存双端事件、抓包、交换面计数器及其哈希。

### 4.6 控制闭环与安全状态

- 分别运行固定 PI 和 `3→8→1` MLP 场景；
- 对三个固定 seed 使用相同的 180 s 对象、扰动和网络故障清单；
- 采集 CONTROL、STATUS、ACK、动作应用和对象轨迹；
- 验证重复控制只执行一次、失联 500 ms 进入安全状态、新会话恢复前旧命令不能生效；
- 从原始数据重算 RMSE、IAE、稳定时间、超调量和闭环延迟。

### 4.7 最终审计

- 在干净副本中重复关键构建和最低完整演示；
- 检查所有报告的命令、退出码、环境、输入输出哈希和结论；
- 核对演示视频时间码与同一候选版本运行编号；
- 重新生成最终 manifest 和 SHA-256，冻结后不再原地改写。
